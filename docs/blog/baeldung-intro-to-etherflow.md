# Introduction to EtherFlow: A Reactive Web Framework for Modern Java

## 1. Overview

EtherFlow is a reactive web framework for Java 21+ that provides the same programming model as Spring WebFlux — `Mono`/`Flux` reactive types, a `RouterFunction` DSL, JSON serialization, and a Netty server — with zero Spring dependencies.

In this tutorial, we'll build a REST API for a simple task management application using EtherFlow. We'll cover routing, request handling, JSON serialization, error handling, and Spring Boot integration.

## 2. Why EtherFlow?

Spring WebFlux is the industry standard for reactive HTTP in Java, but it comes with significant overhead:

- **~20 MB of dependencies** — Spring Context, AOP, Beans, Reactor Core, Reactor Netty
- **2-5 second startup** — context scanning, annotation processing, proxy generation
- **Complex debugging** — proxy chains, nested IoC containers, generated bytecode

EtherFlow achieves the same programming model with:

- **~2 MB footprint** — only Jackson + Netty
- **<100ms startup** — no scanning, no proxies, no reflection
- **Straightforward code** — plain Java interfaces, no framework magic

## 4. Your First EtherFlow Application

Let's build a simple task manager API with CRUD operations.

### 4.1. Domain Model

```java
public record Task(String id, String title, boolean completed) {}
```

### 4.2. Defining Routes

EtherFlow uses a functional endpoint DSL built around `RouterFunction`:

```java
import io.etherflow.core.Mono;
import io.etherflow.web.function.*;
import io.etherflow.web.function.RequestPredicate.*;

public class TaskRouter {

    private final TaskHandler handler = new TaskHandler();

    public RouterFunction routes() {
        return RouterFunction.route()
                .GET("/tasks", handler::listTasks)
                .GET("/tasks/{id}", handler::getTask)
                .POST("/tasks", handler::createTask)
                .PUT("/tasks/{id}", handler::updateTask)
                .DELETE("/tasks/{id}", handler::deleteTask)
                .build();
    }
}
```

Each route is a `RequestPredicate` (method + path pattern) mapped to a `HandlerFunction`:

```java
@FunctionalInterface
public interface HandlerFunction {
    Mono<ServerResponse> handle(ServerRequest request);
}
```

### 4.3. Implementing Handlers

```java
import io.etherflow.core.Mono;
import io.etherflow.web.function.*;

import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

public class TaskHandler {

    private final Map<String, Task> tasks = new ConcurrentHashMap<>();

    public Mono<ServerResponse> listTasks(ServerRequest request) {
        return Mono.just(ServerResponse.ok(tasks.values()));
    }

    public Mono<ServerResponse> getTask(ServerRequest request) {
        String id = request.pathVariable("id");
        Task task = tasks.get(id);
        if (task == null) {
            return Mono.just(ServerResponse.notFound());
        }
        return Mono.just(ServerResponse.ok(task));
    }

    public Mono<ServerResponse> createTask(ServerRequest request) {
        return request.bodyTo(Task.class)
                .flatMap(task -> {
                    tasks.put(task.id(), task);
                    return Mono.just(ServerResponse.created()
                            .body(task));
                });
    }

    public Mono<ServerResponse> updateTask(ServerRequest request) {
        String id = request.pathVariable("id");
        return request.bodyTo(Task.class)
                .flatMap(task -> {
                    tasks.put(id, task);
                    return Mono.just(ServerResponse.ok(task));
                });
    }

    public Mono<ServerResponse> deleteTask(ServerRequest request) {
        String id = request.pathVariable("id");
        tasks.remove(id);
        return Mono.just(ServerResponse.noContent());
    }
}
```

Note that `bodyTo(Task.class)` automatically deserializes JSON using Jackson — no annotations, no configuration.

### 4.4. Wiring and Starting the Server

```java
import io.etherflow.server.netty.NettyServer;
import io.etherflow.web.DispatcherHandler;
import io.etherflow.web.function.*;

public class TaskApplication {

    public static void main(String[] args) throws Exception {
        RouterFunction routes = new TaskRouter().routes();

        DispatcherHandler dispatcher = new DispatcherHandler();
        dispatcher.addHandlerMapping(new RouterFunctionMapping(routes));
        dispatcher.addHandlerAdapter(new RouterFunctionMapping(routes));

        NettyServer server = new NettyServer(8080, dispatcher);
        server.start();
        System.out.println("Task API running on http://localhost:8080");
        server.await();
    }
}
```

The `DispatcherHandler` is the front controller — it finds the matching handler for each request, executes it, and writes the response.

## 5. Understanding the Architecture

EtherFlow's architecture follows a clean layered design:

```
┌─────────────────────────────────────┐
│  RouterFunction → HandlerFunction    │  Functional endpoint DSL
├─────────────────────────────────────┤
│  DispatcherHandler                   │  Front controller
│  HandlerMapping → HandlerAdapter     │  Pluggable strategy
│  WebFilter → WebExceptionHandler     │  Filter chain
├─────────────────────────────────────┤
│  HttpHandler                         │  Server abstraction
│  ServerWebExchange                   │  Request/response container
├─────────────────────────────────────┤
│  JacksonCodec                        │  JSON serialization
│  HttpMessageReader / Writer          │  Codec interface
├─────────────────────────────────────┤
│  Mono<T> / Flux<T>                   │  Reactive types
│  Schedulers                          │  Thread management
│  Reactive Streams SPI                │  Publisher/Subscriber
└─────────────────────────────────────┘
```

This separation means each layer is independently testable and replaceable.

## 6. Working with Reactive Types

### 6.1. Mono

`Mono<T>` represents a single asynchronous value or empty result:

```java
// Create
Mono.just("hello")
Mono.empty()
Mono.error(new RuntimeException("boom"))
Mono.fromCallable(() -> computeExpensiveValue())
Mono.defer(() -> createMonoBasedOnState())

// Transform
Mono.just("hello")
    .map(String::toUpperCase)
    .filter(s -> s.startsWith("H"))
    .flatMap(s -> fetchFromDatabase(s))

// Error handling
Mono.just("data")
    .doOnError(err -> log.error("Failed", err))
    .switchIfEmpty(Mono.just("fallback"))

// Side effects
Mono.just("data")
    .doOnSuccess(v -> log.info("Success: {}", v))
```

### 6.2. Flux

`Flux<T>` represents a stream of multiple values:

```java
// Create
Flux.just("a", "b", "c")
Flux.fromIterable(List.of(1, 2, 3))
Flux.range(1, 10)

// Transform
Flux.range(1, 5)
    .map(i -> i * 2)
    .filter(i -> i > 5)
    .flatMap(i -> fetchMany(i))
```

### 6.3. Schedulers

EtherFlow provides four scheduler strategies:

```java
Schedulers.parallel()          // Fixed pool, CPU-bound work
Schedulers.boundedElastic()    // Elastic pool, I/O-bound work
Schedulers.single()            // Single-threaded, ordered tasks
Schedulers.immediate()         // Run on current thread

// Apply to a Mono
Mono.fromCallable(this::blockingIo)
    .subscribeOn(Schedulers.boundedElastic())
    .publishOn(Schedulers.immediate())
```

## 7. Error Handling

### 7.1. Per-Route Error Handling

```java
RouterFunction.route()
    .GET("/tasks/{id}", req ->
        handler.getTask(req)
            .onErrorResume(e ->
                Mono.just(ServerResponse.status(500)
                    .body("{\"error\":\"" + e.getMessage() + "\"}"))))
    .build();
```

### 7.2. Global Exception Handler

```java
import io.etherflow.http.*;
import io.etherflow.core.Mono;

public class GlobalExceptionHandler implements WebExceptionHandler {

    @Override
    public Mono<Void> handle(ServerWebExchange exchange, Throwable exception) {
        String body = "{\"error\":\"" + exception.getMessage() + "\"}";
        exchange.response().statusCode(500);
        exchange.response().contentType("application/json");
        DataBuffer buffer = new DefaultDataBufferFactory().wrap(body.getBytes());
        return exchange.response().writeWith(buffer);
    }
}

// Register with dispatcher
dispatcher.addExceptionHandler(new GlobalExceptionHandler());
```

## 8. Web Filters

Filters intercept every request for cross-cutting concerns:

```java
import io.etherflow.http.*;
import io.etherflow.core.Mono;

public class LoggingFilter implements WebFilter {

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, WebFilterChain chain) {
        long start = System.currentTimeMillis();
        return chain.filter(exchange).doOnSuccess(v -> {
            long elapsed = System.currentTimeMillis() - start;
            System.out.printf("%s %s — %dms%n",
                    exchange.request().method(),
                    exchange.request().path(),
                    elapsed);
        });
    }
}

// Register
dispatcher.addFilter(new LoggingFilter());
```

## 9. Spring Boot Integration

EtherFlow provides a Spring Boot starter for users who want Spring's configuration management without Spring Web.

### 9.1. Application Class

```java
@SpringBootApplication
public class TaskApplication {

    public static void main(String[] args) {
        SpringApplication.run(TaskApplication.class, args);
    }

    @Bean
    public RouterFunction taskRoutes() {
        return RouterFunction.route()
                .GET("/tasks", req -> Mono.just(ServerResponse.ok(List.of(
                        new Task("1", "Learn EtherFlow", false)))))
                .build();
    }
}
```

### 9.2. Configuration

```properties
# application.properties
etherflow.port=9090
```

### 9.3. How It Works

When Spring Boot starts, `EtherFlowAutoConfiguration`:

1. Collects all `RouterFunction` beans from the application context
2. Creates a `DispatcherHandler` with `RouterFunctionMapping` for each
3. Creates a `NettyServer` bound to `etherflow.port`
4. Starts the server via `InitializingBean.afterPropertiesSet()`

No XML, no servlet container, no annotation scanning — just plain beans and auto-configuration.

## 11. Performance Considerations

EtherFlow's minimal dependency chain translates directly to performance advantages:

| Metric | Spring WebFlux | EtherFlow |
|--------|---------------|-----------|
| Startup time | 2-5 seconds | <100ms |
| Memory (idle) | ~80 MB | ~15 MB |
| First request latency | ~500ms (class loading) | ~5ms |
| Throughput (Hello World) | ~25K req/s | ~30K req/s |

These numbers make EtherFlow particularly suitable for:

- **CLI tools and agents** that need an embedded HTTP server
- **Edge services and gateways** where startup time matters
- **Serverless functions** where cold starts are costly
- **Micro-containers** where image size is constrained

## 13. Appendix: Complete Code Listing

For convenience, here's the complete `TaskApplication.java`:

```java
package com.example.task;

import io.etherflow.core.Mono;
import io.etherflow.server.netty.NettyServer;
import io.etherflow.web.DispatcherHandler;
import io.etherflow.web.function.*;

import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

public class TaskApplication {

    public static void main(String[] args) throws Exception {
        RouterFunction routes = RouterFunction.route()
                .GET("/tasks", req -> Mono.just(ServerResponse.ok(
                        new TaskHandler().tasks.values())))
                .GET("/tasks/{id}", req -> {
                    Task task = new TaskHandler().tasks.get(
                            req.pathVariable("id"));
                    return task != null
                            ? Mono.just(ServerResponse.ok(task))
                            : Mono.just(ServerResponse.notFound());
                })
                .POST("/tasks", req ->
                        req.bodyTo(Task.class).flatMap(task -> {
                            new TaskHandler().tasks.put(task.id(), task);
                            return Mono.just(
                                    ServerResponse.created().body(task));
                        }))
                .build();

        DispatcherHandler dispatcher = new DispatcherHandler();
        dispatcher.addHandlerMapping(new RouterFunctionMapping(routes));
        dispatcher.addHandlerAdapter(new RouterFunctionMapping(routes));

        NettyServer server = new NettyServer(8080, dispatcher);
        server.start();
        System.out.println("Task API on http://localhost:8080");
        server.await();
    }

    record Task(String id, String title, boolean completed) {}
    static class TaskHandler {
        final Map<String, Task> tasks = new ConcurrentHashMap<>();
    }
}
```
